# Issueを書く

このリポジトリのIssueを、日本語で背景・目標・判断できる完了条件に整理する。

## タイトル

変更後の状態や行いたい作業を短く具体的に表す。連番・作業順の数字を先頭に付けない。
順序や依存は本文でGitHubのIssue番号（例：#2）を参照する。

## 本文

見出しは次の3つを、この順序で使う。

- `## 背景`：現在の状態、困っていること、なぜ必要か。依存Issueがあればここに記載する。
- `## 実現したいこと`：変更後にできることと今回の範囲。実装手段が未決定なら提案と分かるようにする。
- `## 完了条件`：確認可能な結果を `- [ ]` で列挙する。

既存Issueの更新では、決定済みの要件・依存・検証条件とチェック済みの状態を保持する。
不足情報を事実として補わず、判断が必要なら本文に明記する。
目的・範囲・依存・検証のために別の最上位見出しを増やさず、上の3項目に含める。

## 例

タイトル：HTMLレポートをPDFで保存できるようにする

```markdown
## 背景

HTMLのイベント一覧を、印刷やファイル共有にも使いたい。HTML生成に対応する #5 の完了後に取り組む。

## 実現したいこと

生成済みHTMLから、日本語が読める配布用PDFを保存できるようにする。

## 完了条件

- [ ] HTMLからPDFファイルを生成できる。
- [ ] 日本語の文字欠けや、イベント情報が切れる改ページがないことを確認する。
- [ ] PDFから出典リンクを開ける。
```

## GitHubへの反映

原稿の作成とGitHubへの登録・更新を区別し、依頼された範囲だけ反映する。
登録前に既存Issueを確認して重複を避ける。既存の更新は番号を維持する。
ghを使う場合は本文をファイルに保存し、`--body-file`で渡す。
反映後はタイトル・本文を取得し直して確認し、Issueのリンクを報告する。
