# Issue一覧

GitHub Issues #1〜#8に登録済み。本文は専用skillの形式に統一する。

## [#1 開発環境とリポジトリ基盤を整備する](https://github.com/oddgai/fuchu-kids-event-curator/issues/1)

### 背景

まだ初期構成がなく、開発・検証の手順も整っていない。Go本体はPCのグローバルに直接入れず、miseでプロジェクト単位に管理したい。

### 実現したいこと

Goで開発・検証を再現できる最小構成を作る。

miseによるGo安定版のプロジェクト単位の固定、go.mod、最小CLI、README、.gitignore、AGENTS.md、Issueテンプレート、CI。

Issueの書き方を統一する専用skillを整備し、AGENTS.mdから参照する。既存の汎用skillsは重複コピーしない。

### 完了条件

- [ ] 新しい環境で準備と検証を再現する手順がある。
- [ ] mise.tomlでGoの具体的なバージョンを固定し、CIでも同じ指定を利用する。
- [ ] Goをシステムに直接インストールせず、miseのグローバル設定も変更しない。mise execによる実行を案内する。
- [ ] gofmt、go vet ./...、go test ./...が成功し、CIも同じコマンドを実行する。
- [ ] 最小CLIの起動・ヘルプを確認できる。
- [ ] ブラウザ・収集依存は、この段階で必要なものだけ導入する。

## [#2 初期7サイトの取得方法を調査する](https://github.com/oddgai/fuchu-kids-event-curator/issues/2)

### 背景

情報源は7サイトあるが、一覧・詳細ページの構造と取得方式は未検証。#1 の完了後に取り組む。

### 実現したいこと

### 完了条件

- [ ] 利用条件・robots.txtを確認し、アクセス間隔の方針を記録する。
- [ ] HTTP取得で足りるか、JavaScript実行が必要かを実際に検証する。
- [ ] 公園の継続収集用一覧URLを特定する。
- [ ] HTMLにない情報、対象年齢の記載状況、取得できないサイトを明記する。
- [ ] 最初に実装する1サイトを選ぶ。OCRは含めない。

## [#8 手動・定期実行と成果物保存を整備する](https://github.com/oddgai/fuchu-kids-event-curator/issues/8)

### 背景

手動操作を毎回行わず、2週間または1ヶ月ごとに候補をまとめたい。#6 の完了後に取り組み、#7 の全サイト対応完了は必須としない。

### 実現したいこと

定期的に最新の候補を受け取れる運用にする。

### 完了条件

- [ ] GitHub Actionsから手動実行できる。
- [ ] 14日間隔・月2回・毎月のどれにするかを決め、掲載期間とは別に設定する。
- [ ] JSON・HTML・PDF・PNGの保存先・保持期間・ダウンロード方法を記録する。
- [ ] サイト別の失敗がログとレポートで確認でき、全件失敗は正常終了として扱わない。
- [ ] キャッシュを導入する場合も過去データであることが分かる。
- [ ] 子供の生年月日や自宅住所を公開リポジトリに保存しない。
