# ルール判定 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 29件の評価を根拠付きルールへ反映し、候補と期間情報・要確認を分ける。
**Architecture:** 本文/参加条件抽出 → 内容判定 → 期間・参加条件 → 掲載先。人手の根拠文はURL/タイトル一致時だけ補足する。
**Tech Stack:** Go標準ライブラリ、既存goquery/chromedp。
**Spec:** docs/specs/rule-feedback.md

## Global Constraints

- AI API・OCRを追加しない。
- 好みと開催期間/参加条件を分ける。
- 判定理由と根拠を保存する。無記載を参加可能としない。
- 未マージPR #16上の作業ブランチを基点とし、自動マージしない。

## Review Focus

- 幼児入場可と一般的な禁止案内が同居する公演。
- 親子/ファミリーの名称と年齢制限が衝突する例。
- 公園優先でも対象4歳・満員が優先する。
- ナイトプレーパークの個別例外と昼間優先の両立。
- 同一URLでもタイトルが変わった場合に人手の条件を再利用しない。
