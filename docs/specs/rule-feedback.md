# フィードバックを反映するルール判定

ユーザーは29件を評価し、最初はAIを使わずルールで判定する方針を選択した。

## 判断を分ける

- 内容への好み：recommend / exclude / information / review。プレーパーク・幼児歓迎・ファミリーコンサート・遊具・幼児の乗車を肯定材料とする。
- 参加条件：明示された年齢、未就学児の入場/同伴禁止、中止・受付終了を優先する。肯定的な名称や情報源で制限を打ち消さない。
- 掲載先：条件と日付が確認できた候補、期間限定情報、要確認、除外（JSON監査用）。日程不明はおすすめへ混ぜない。

飲食中心、落語、清掃、バックヤードツアー等は現在の好みでは優先しない。ただし幼児向けの具体的な遊びがある場合は別に扱う。公園サイトは肯定の補助であり、年齢・満員・中止の条件は優先する。
昼間を優先し、18時以降のみの催しは原則除外する仮のルールを置く。明示的にOKだったナイトプレーパークは例外として警告付き候補にする。
イルミネーションはイベント候補と分けて期間情報として掲載。集合ページは個別企画の確認へ回す。

## 根拠とフィードバック

本文の短い紹介だけでは判断材料を失うため、内容判定用本文と、イベント全体に適用する参加条件の文章を別フィールドに保存する。別企画の対象条件を親イベントへ混ぜない。
確認済みの画像内条件などはfeedback/reviews.jsonの人手の根拠文で補足する。URLとタイトルが一致するものだけを適用し、人手確認と明示する。取得日が確認日から90日を超えた場合は補足を適用せず再確認する（仮置き）。OK/NGの値自体を実行時の判定に直接使用しない。
29件は内容評価用の回帰データ。期間外・満員などによる掲載可否とは別に比較する。同じ29件の一致率は未知イベントの精度とは呼ばない。別名・未知URL・制限付き肯定例などもテストする。

## 範囲外

AI API、画像OCR、サイト承諾の代行、PRの自動マージ。既存のJSONも読み込めるが、保存されていない本文は復元できないため再取得または要確認とする。
